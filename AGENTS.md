# Инструкция для ИИ-агента

Ты подключился к проекту **SETA** — корпоративному Telegram-ассистенту руководителя.
Этот файл — точка входа. Прочитай его целиком, затем файлы из `agent/` в указанном порядке.

## Порядок чтения

| Шаг | Файл | Что даёт |
|-----|------|----------|
| 1 | `agent/CONTEXT.md` | Кто заказчик, какую задачу решаем, что уже известно об организации |
| 2 | `agent/DECISIONS.md` | Все принятые решения и **почему именно так**. Не пересматривай их без разговора с владельцем |
| 3 | `agent/STATE.md` | Что готово прямо сейчас, что следующее, как запустить и проверить |
| 4 | `agent/ARCHITECTURE.md` | Модель данных, права, слои, границы модулей |
| 5 | `agent/CONVENTIONS.md` | Как писать код в этом проекте |
| 6 | `agent/HISTORY.md` | Журнал сессий: что менялось и когда |
| 7 | `STRUCTURE.md` | Что лежит в каждой папке и зачем нужен каждый файл |

Полное техническое описание продукта — `Архитектура SETA.html` (открыть в браузере).
Исходная постановка от заказчика — `Проект Бот.txt`.

## Главные правила проекта

1. **Система считает — ИИ объясняет.** Просрочки, свободные окна, статусы, выгрузки
   считает детерминированный код. Языковая модель работает только поверх готовых цифр.
   Отключение ИИ не должно ломать ни одну функцию.
2. **Роль, выбранная пользователем самому себе, — это заявка, а не право.**
   Повышенные роли выдаёт только человек.
3. **Право не равно доступу.** Каждая запись проверяется дополнительно:
   я автор? исполнитель? проверяющий? мой отдел?
4. **Скрытых действий от чужого имени не бывает.** Действие по делегированию
   подписывается «по поручению» и пишется в журнал с настоящим автором.
5. **Эскалация фильтрует, а не транслирует.** Руководителю — только сводкой.
6. **Секреты только в `.env`.** Никогда в код, в репозиторий и в переписку.
7. **Ручные правки боевой базы запрещены.** Любое изменение схемы — миграция Alembic.

## Что делать в начале работы

```bash
cd seta
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d
docker compose -f docker-compose.yml -f docker-compose.dev.yml \
  run --rm --no-deps migrate python scripts/smoke_block1.py
docker compose -f docker-compose.yml -f docker-compose.dev.yml \
  run --rm --no-deps migrate python scripts/smoke_block2.py
docker compose -f docker-compose.yml -f docker-compose.dev.yml \
  run --rm --no-deps migrate python scripts/stress_test.py
```

Все три должны показать `Ошибок: 0`. Если нет — сначала чини, потом делай новое.

## Что делать в конце работы

1. Обнови `agent/STATE.md` — что стало готово, что следующее.
2. Допиши запись в `agent/HISTORY.md` — дата, что сделано, что проверено.
3. Если менялись решения — обнови `agent/DECISIONS.md` с обоснованием.
4. Если менялась схема или правила — обнови `agent/ARCHITECTURE.md`.
5. Обнови `README.md`, если изменилось то, что видит пользователь.
6. Закоммить и запушь. Владелец просил обновлять репозиторий каждый раз.

## Язык

Владелец пишет по-русски. Весь интерфейс, комментарии в коде и документация — на русском.
Код (имена переменных, функций, таблиц) — на английском.
