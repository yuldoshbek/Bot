# SETA — корпоративный ассистент руководителя

Telegram-система управления встречами, поручениями и контролем исполнения.
Полное описание архитектуры — в файле `../Архитектура SETA.html`.

Готовы **блоки 1–4**: регистрация и права на уровне записи, индикатор
доступности руководителя, поручения со сроками и проверкой качества, календарь
и встречи с подбором свободных окон, реестр решений, документы с поиском
по содержимому, выгрузка в Excel и PDF, журнал аудита, администрирование
в боте, раздел состояния `/health`.
Следующий — блок 5, Mini App и дашборды.

---

## Запуск за три шага

### 1. Заполните `.env`

Файл уже создан из `.env.example`. Обязательны две строки:

```
BOT_TOKEN=сюда_токен_от_BotFather
BOOTSTRAP_ADMIN_TELEGRAM_ID=ваш_числовой_id
```

Свой Telegram ID можно узнать двумя способами: написать боту `@userinfobot`,
либо запустить систему (шаг 2) и отправить своему боту команду `/id`, после чего
вписать число в `.env` и перезапустить.

Токен нигде, кроме `.env`, не хранится: файл в `.gitignore` и в образ не попадает.

### 2. Запустите

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d
```

Миграции применяются автоматически перед стартом бота.

### 3. Проверьте

Откройте своего бота в Telegram и отправьте `/start`.

Состояние системы — в браузере: **http://127.0.0.1:8010/health**
Там видно, живы ли бот и фоновые циклы, не встала ли очередь и что падало.

```bash
docker compose logs -f bot     # подробности, если нужны
```

## Первые действия администратора

1. `/start` → в меню появится **🛠 Администрирование**.
2. **Отделы → Добавить отдел** — заведите подразделения.
3. **Ссылки-приглашения** — выберите отдел, бот выдаст готовую ссылку.
   Отправьте её в чат отдела: все, кто перейдёт, получат роль «Сотрудник»
   автоматически, подтверждать вручную ничего не нужно.
4. Руководителю и ассистенту роль назначается вручную: они регистрируются
   сами, а вы подтверждаете заявку кнопкой **✅ Принять**.

## Индикатор доступности

Руководитель нажимает **🟢 Моя доступность** и одним касанием сообщает, что
принимает сейчас: 30 минут, час, до конца дня или поздний приём. Сотрудники
видят это в разделе **👤 Кто на связи** и обращаются без заявки.

У состояния всегда есть срок — по его истечении индикатор снимается сам.
Вечного «доступен» не бывает: иначе через неделю ему перестанут верить.

## Календарь и встречи

Сотрудник нажимает **«Запросить встречу»**, выбирает длительность и тему —
и получает список свободных окон руководителя. Окна считаются по-настоящему:
рабочие часы, обед, праздники и перенесённые рабочие дни, отпуска, личные
блокировки, буфер между встречами, предел встреч подряд. Если в заявке есть
другие участники, берётся пересечение их доступности, а не сумма.

Выбранное окно **резервируется сразу**, а не когда руководитель ответит. Иначе
между «выбрал» и «одобрено» проходит час, и то же время успевают выбрать ещё
трое. Удержание живёт до конца рабочего дня или до решения; если ответа нет,
окно возвращается в оборот само, и человек об этом узнаёт.

Отказ всегда предлагает выход: не «это время занято», а «это время занято,
свободны 10:30 и 11:00».

Руководитель переносит и отменяет встречи с обязательной причиной — её видят
все участники. За пять минут до начала приходит кнопка «Я на месте»; опоздание
записывается в минутах, но выводов система не делает. После встречи —
оценка одним касанием, её видят только руководитель и ассистент.

Лимит времени задаётся на отдел с личными исключениями. Превышение не
запрещает заявку, а помечает её: срочный вопрос не должен упираться в норму,
но и расходоваться время не должно молча.

## Встреча → решение → документ

Совещание заканчивается — и итоги фиксируются, пока их помнят. В карточке
встречи: повестка с отметкой «рассмотрено», кнопка «Завершить», а сразу после
неё — «Решение» и «Поручение». Три решения и три поручения с ответственными
и сроками заносятся за минуту, не выходя из карточки.

**Реестр решений** живёт дольше встреч. Решение не удаляется: его закрывают
выполненным или отменяют с причиной, и строка остаётся навсегда. Через полгода
вопрос «а что мы тогда решили по складу» находит ответ.

**Документы** — просто пришлите файл боту. Он спросит, кому его открыть; по
умолчанию документ виден только вам. Фоновый обработчик достаёт текст из PDF,
DOCX, XLSX и TXT, и файл начинает находиться поиском по фразе из его содержимого.

**Доступ к встрече не даёт доступа к её документам.** Участник совещания видит,
что документ приложен, но получит его только если загрузивший открыл доступ.
Каждое открытие пишется в журнал, и владелец файла видит, кто его читал.

**Поиск** ищет сразу по встречам, поручениям, решениям, людям и содержимому
документов. Понимает формы слов: «совещаний» найдёт «совещание». Прощает
опечатку в фамилии. Находится только то, что вам открыто, — и это не отсев
готового списка, а условие самого запроса.

**Выгрузка** в Excel и PDF отдаёт ровно то, что видно на экране, — ни строкой
больше.

## Команды разработки

```bash
# проверки: smoke_block1 (35), smoke_block2 (52), smoke_block3 (156),
# smoke_block4 (160), smoke_hardening (51), stress_test (62) — всего 516
docker compose -f docker-compose.yml -f docker-compose.dev.yml \
  run --rm --no-deps migrate python scripts/smoke_block1.py

# новая миграция после правки моделей
docker compose -f docker-compose.yml -f docker-compose.dev.yml \
  run --rm --no-deps migrate alembic revision --autogenerate -m "описание"

# применить миграции
docker compose -f docker-compose.yml -f docker-compose.dev.yml run --rm migrate

# консоль базы
docker compose exec postgres psql -U seta -d seta

# остановить всё
docker compose down
```

Порты подобраны так, чтобы не конфликтовать с другими проектами на этой машине:
Postgres — `55432`, Redis — `56379`, API — `8010`.

## Структура

```
app/
  core/        конфигурация, база, Redis, время, разбор сроков, экранирование
  models/      40 таблиц: люди и права, расписание, встречи, решения,
               поручения, документы, журналы
  services/    права, регистрация, доступность, окна календаря, встречи, явка,
               лимиты времени, решения, документы, поиск, досье, выгрузка,
               поручения, сроки, уведомления, состояние
  bot/         Telegram: обработчики, клавиатуры, middleware авторизации
  workers/     доставка уведомлений и контроль сроков
  api/         HTTP: вебхук, /health со страницей состояния
migrations/    версии схемы (Alembic), шесть миграций
scripts/       проверки, резервное копирование, восстановление
```

## Переезд на сервер

1. Скопировать папку и `.env` на сервер.
2. `BOT_MODE=webhook`, `WEBHOOK_BASE_URL=https://ваш-домен`, новый `WEBHOOK_SECRET`.
3. `docker compose up -d` (без dev-оверрайда).
4. Поставить Caddy или Nginx перед `api` для HTTPS.

Переезд между провайдерами — копирование папки и дампа базы, привязки к
конкретному хостингу в системе нет.
