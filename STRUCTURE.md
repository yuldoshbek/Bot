# Структура проекта

Что лежит в каждой папке и зачем нужен каждый файл. Обновляется вместе с кодом.

```
Проект Телеграм Бот/
├── AGENTS.md                  точка входа для ИИ-агента
├── README.md                  описание продукта: что работает, как запустить
├── STRUCTURE.md               этот файл
├── .gitignore                 что не попадает в репозиторий (в первую очередь .env)
├── .githooks/                 защита от утечки секретов
├── agent/                     память проекта
├── backups/                   резервные копии базы (в репозиторий не попадают)
├── seta/                      исходный код системы
├── Архитектура SETA.html      полный технический документ для руководства и IT
├── Отчёт по ядру SETA.html    отчёт о выполненных работах по блоку 1
└── Проект Бот.txt             исходная постановка задачи от заказчика
```

| Файл | Назначение |
|---|---|
| `pre-commit` | Не даёт закоммитить токен Telegram, ключ OpenAI или файл `.env`. Включается один раз: `git config core.hooksPath .githooks` |

## `agent/` — память проекта

Всё, что нужно новому человеку или ИИ-агенту, чтобы продолжить работу без пересказа
истории переписки. Читается в порядке, указанном в `AGENTS.md`.

| Файл | Назначение |
|---|---|
| `CONTEXT.md` | Кто заказчик, какую задачу решаем, что известно об организации, чем измеряется успех, главный риск |
| `DECISIONS.md` | 18 принятых решений с обоснованиями: стек, отказ от Firebase, ИИ, права, эскалация, хостинг |
| `ARCHITECTURE.md` | Техническая карта: слои, все таблицы, устройство прав, что построено и что запланировано |
| `STATE.md` | Что готово прямо сейчас, что не сделано, как запустить и проверить, состав следующего блока |
| `CONVENTIONS.md` | Как писать код в этом проекте: стиль, обязательные проверки прав, правила миграций, аудита и тестов |
| `HISTORY.md` | Журнал сессий: что менялось, что проверено, какие инциденты были и какие выводы сделаны |
| `PLAN-block3.md` | Фазовый план календаря: восемь фаз, у каждой проверка и анти-паттерны |

## Память проекта и claude-mem

Плагин claude-mem пишет наблюдения автоматически в `~/.claude-mem` — **только на этой
машине**, вне репозитория. Это черновик: он помнит, что делалось, но не помнит, почему.
Источник истины — папка `agent/`, которая версионируется вместе с кодом и переживает
смену машины. Правило разрешения противоречий записано в `AGENTS.md`.

## `seta/` — система

### Корень

| Файл | Назначение |
|---|---|
| `docker-compose.yml` | Боевой запуск: postgres, redis, migrate, bot, worker, api |
| `docker-compose.dev.yml` | Оверрайд для разработки: исходники монтируются внутрь, правка кода без пересборки |
| `Dockerfile` | Образ приложения на Python 3.13-slim |
| `requirements.txt` | Зависимости с минимальными версиями |
| `alembic.ini` | Настройка миграций |
| `.env.example` | Шаблон настроек. **Только заглушки — секретов здесь быть не должно** |
| `.dockerignore` | Что не копируется в образ |
| `README.md` | Инструкция по запуску и обслуживанию |

### `app/core/` — общая основа

| Файл | Назначение |
|---|---|
| `config.py` | Все настройки из переменных окружения. Единственный источник конфигурации |
| `db.py` | Подключение к PostgreSQL, транзакция на действие (`session_scope`) |
| `redis.py` | Подключение к Redis, распределённые блокировки |
| `timeutil.py` | Время: хранение в UTC, показ в поясе пользователя, тихие часы |
| `dates.py` | Разбор срока, написанного человеком: «до пятницы», «через 3 дня», «05.09» |
| `text.py` | Экранирование пользовательского текста перед вставкой в HTML-сообщение |

### `app/models/` — таблицы базы

| Файл | Таблицы |
|---|---|
| `base.py` | Базовый класс, общие столбцы `id`, `created_at`, `updated_at` |
| `enums.py` | Все перечисления: роли, статусы, приоритеты, области видимости |
| `org.py` | `organizations`, `departments` |
| `user.py` | `users`, `invites` |
| `rbac.py` | `roles`, `permissions`, `role_permissions`, `user_roles`, `delegations` |
| `schedule.py` | `working_hours`, `availability_states`, `availability_log`, `calendar_blocks`, `absences`, `holidays` |
| `task.py` | `tasks`, `task_events`, `task_comments`, `task_extensions`, `task_templates` |
| `notification.py` | `notifications` — очередь с защитой от дублей |
| `audit.py` | `audit_log` — только добавление записей |

### `app/services/` — бизнес-логика

Здесь живут правила системы. Обработчики бота ничего не решают сами: они собирают
ответ и вызывают сервис.

| Файл | Назначение |
|---|---|
| `rbac.py` | Каталог 28 прав, матрица ролей, загрузка прав пользователя, проверка доступа к конкретной записи |
| `registration.py` | Три пути регистрации, приглашения, подтверждение заявок, правило первого администратора |
| `availability.py` | Индикатор доступности руководителя: включение, истечение срока, «кто на связи» |
| `tasks.py` | Поручения: создание, все переходы состояний, проверка качества, продление сроков, комментарии, выборки |
| `deadlines.py` | Сроки, просрочки и эскалация по утверждённым порогам |
| `notifications.py` | Постановка в очередь и доставка: дедупликация, тихие часы, группировка |
| `audit.py` | Единственный способ добавить запись в журнал аудита |
| `bootstrap.py` | Первичное наполнение: организация, роли, права, рабочие часы. Безопасно к повторам |

### `app/bot/` — Telegram

| Файл | Назначение |
|---|---|
| `loader.py` | Экземпляры бота и диспетчера, хранилище состояний в Redis |
| `run.py` | Запуск в режиме long polling, подключение обработчиков, перехват необработанных ошибок |
| `utils.py` | Безопасный разбор данных из нажатых кнопок |
| `middlewares/auth.py` | На каждое обновление: транзакция, поиск сотрудника, загрузка прав, отсечение неподтверждённых |
| `keyboards/common.py` | Все клавиатуры: меню по ролям, выбор роли, подтверждение заявок, доступность |
| `handlers/start.py` | Вход и регистрация, приглашения, подтверждение телефона |
| `handlers/admin.py` | Администрирование: заявки, сотрудники, отделы, ссылки, журнал |
| `handlers/availability.py` | Индикатор доступности и раздел «кто на связи» |
| `handlers/tasks.py` | Поручения: создание, списки, карточка, все действия, контроль |
| `handlers/menu.py` | Профиль, помощь, честные заглушки для будущих блоков |

### `app/workers/` — фоновые процессы

| Файл | Назначение |
|---|---|
| `runner.py` | Два цикла: доставка уведомлений каждые 3 секунды, проверка сроков раз в минуту. Оба под блокировкой Redis |

### `app/api/` и `app/main.py` — HTTP

| Файл | Назначение |
|---|---|
| `main.py` | Приём вебхука Telegram с проверкой секретного токена и `/health` для мониторинга |
| `api/v1/` | Заготовка под API для Mini App (блок 5) |

### `migrations/` — версии схемы базы

| Файл | Назначение |
|---|---|
| `env.py` | Настройка Alembic под асинхронный движок |
| `versions/992adea33371_block1_core.py` | Блок 1: организация, люди, роли, права, расписание, аудит — 16 таблиц |
| `versions/616f2abfae00_block2_tasks_notifications.py` | Блок 2: поручения, события, комментарии, продления, шаблоны, уведомления — 6 таблиц |
| `versions/a1c4e7b9d200_hardening.py` | Укрепление: расширения, границы организаций, ступени эскалации, частичные индексы, запрет пересечений |

Схема меняется **только** миграциями. Ручные правки боевой базы запрещены.

### `scripts/` — проверки и обслуживание

| Файл | Назначение |
|---|---|
| `smoke_block1.py` | Проверка ядра: 35 сценариев — регистрация, права, доступность, аудит |
| `smoke_block2.py` | Проверка поручений: 52 сценария — полный путь, возвраты, продления, эскалация, уведомления |
| `smoke_hardening.py` | Проверка укрепления: 41 сценарий — область прав, границы организаций, откат доставки, ступени эскалации |
| `backup.sh` | Ежедневная копия базы, хранение 14 дней, проверка целостности |
| `restore.sh` | Восстановление из копии с подтверждением и остановкой служб |
| `stress_test.py` | Злонамеренная проверка: одна кнопка десять раз, гонки, чужие идентификаторы, мусорный ввод, скорость |
| `make_admin.py` | Аварийная выдача прав администратора, если доступ потерян |

Все проверки создают данные только в организациях с названием «ТЕСТ …» и удаляют
их строго по `organization_id`. Боевые записи недосягаемы.

## Как всё связано

```
человек в Telegram
      ↓
handlers/*.py         собирают ответ, ничего не решают
      ↓
middlewares/auth.py   транзакция + кто это + какие права
      ↓
services/*.py         все правила системы
      ↓
models/*.py           таблицы PostgreSQL
      ↓
notifications         очередь с защитой от дублей
      ↓
workers/runner.py     доставка и контроль сроков
```
