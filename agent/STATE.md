## Готово

### Блок 1 — Ядро

- **Регистрация** тремя путями: ссылка отдела, свободная заявка, персональная
  одноразовая ссылка. Завершается подтверждением номера телефона кнопкой Telegram.
- **Роли и права:** 6 ролей, 28 прав, 69 связок с областями видимости.
  Проверка на уровне отдельной записи, а не только права.
- **Делегирование:** модель готова, интерфейс выдачи — в блоке 2.
- **Индикатор доступности** руководителя с автоматическим истечением и поздним приёмом.
- **Рабочее время:** 09:00–19:00, обед, буфер, выходные, поздний предел.
- **Журнал аудита:** только добавление, «было/стало», настоящий автор при делегировании.
- **Администрирование в боте:** заявки, сотрудники, отделы, ссылки-приглашения, журнал.
- **Инфраструктура:** Docker Compose, миграции Alembic, `/health`, dev-оверрайд
  с монтированием исходников.

### Блок 2 — Поручения и контроль

- **Создание** за четыре шага: кому, что, срок словами («до пятницы», «через 3 дня»,
  «05.09»), приоритет. Ассистент создаёт от имени руководителя — в карточке видно обоих.
- **Жизненный цикл:** Новое → Принято → В работе → На проверке → Выполнено,
  плюс Заблокировано / Просрочено / Отменено. Все переходы в одном месте
  (`app/services/tasks.py`), каждый пишет событие в историю.
- **Проверка качества:** включается автоматически для приоритетов Высокий
  и Критичный. Возврат на доработку требует комментария. Возвраты считаются.
- **Продление срока:** исполнитель просит с обоснованием, автор решает.
  Каждое продление сохраняется — видно, кто хронически двигает сроки.
- **Комментарии и файлы** внутри поручения.
- **Сроки и эскалация** по порогам Р-10, с фильтрацией: руководителю поштучно
  ничего не приходит, кроме поручений на личном контроле.
- **Уведомления:** дедупликация по `event_key` на уровне таблицы, тихие часы
  сдвигают доставку, четыре и более обычных сообщений объединяются в одно.
- **Фоновый обработчик** (`app/workers/runner.py`): доставка каждые 3 секунды,
  проверка сроков раз в минуту, распределённая блокировка в Redis.

## Как запустить

```bash
cd seta
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d
docker compose logs -f bot        # ожидается: Run polling for bot @...
curl http://127.0.0.1:8010/health # ожидается: api/database/redis = ok
```

Порты: Postgres 55432, Redis 56379, API 8010 — стандартные заняты
другими проектами владельца.

## Следующий блок: календарь и встречи

Состав:

1. Рабочие часы, обед, буферы, праздники, отпуска — расчёт свободных окон.
2. Заявка на встречу: выбор руководителя, длительность, предпочтительное время.
3. Удержание слота на время рассмотрения, автоматическое освобождение.
4. Подтверждение и отклонение заявки, перенос с уведомлением всех участников.
5. Быстрое совещание: тема, участники, длительность.
6. Лимиты времени руководителя на сотрудника и отдел.
7. Отметка явки и оценка встречи одним касанием.

**Критерий готовности:** сотрудник запросил встречу, получил окна, руководитель
подтвердил одной кнопкой, все получили уведомления, двойное бронирование
одного окна оказалось невозможным.

**Что понадобится от владельца:** 2–3 человека для проверки живого сценария.
