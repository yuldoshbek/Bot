# Контекст проекта

## Что это

**SETA** (Smart Executive Telegram Assistant) — корпоративная система управления
рабочим временем, встречами, решениями, поручениями и контролем исполнения.
Telegram — интерфейс, вся логика на сервере.

Это не «бот с календарём». Продукт существует ради одного замкнутого цикла:

```
Запрос → Свободное окно → Встреча → Решение → Поручение →
Исполнитель → Срок → Контроль → Проверка → Результат → Сводка руководителю
```

Сегодня этот круг разорван в трёх местах: устное поручение нигде не фиксируется,
срок помнит только ассистент, результат проверяется тогда, когда о нём вспомнили.
Система закрывает эти три разрыва. Всё остальное вторично.

## Что известно об организации

- Руководитель верхнего уровня **один** (замдиректора), но архитектура рассчитана
  на нескольких: у каждого свой календарь, свои правила, свои ассистенты.
- Отделы: проектные подразделения, HR, обычные сотрудники. Точный список
  заводится владельцем в админке — жёстко в коде его нет.
- **Централизованного календаря в организации нет.** Наша система — единственный
  источник истины. Внешних календарных интеграций не строим.
- Корпоративного каталога сотрудников (AD/LDAP) нет. Регистрация — через бота.
- Рабочий день: **09:00–19:00**, обед 13:00–14:00. Бывают поздние встречи —
  для них есть отдельный механизм (см. «поздний приём» в ARCHITECTURE.md).

## Цель, по которой измеряется успех

Проект успешен не когда в нём много функций, а когда через несколько недель:

- руководитель говорит: «мне стало легче управлять днём»;
- сотрудник говорит: «мне не пришлось учиться, я просто нажал кнопку»;
- ассистент говорит: «я больше не держу в голове все встречи и сроки».

## Главный риск

Не технический. **Руководитель может не начать пользоваться.** Поэтому:
ассистент — основной пользователь, продукт полезен даже если руководитель
открывает только утреннюю сводку и жмёт две кнопки. Всё, что требует от
руководителя больше одного касания, должно быть перепроверено на необходимость.
