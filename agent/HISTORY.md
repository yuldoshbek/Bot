## 31 августа 2026 (ночь, продолжение) — Блок 2: поручения и контроль

Реализован блок 2 целиком: 6 новых таблиц (`tasks`, `task_events`, `task_comments`,
`task_extensions`, `task_templates`, `notifications`), миграция `616f2abfae00`.

Ключевые решения реализации:

- **Все переходы состояний собраны в `app/services/tasks.py`.** Обработчики бота
  не меняют статус напрямую — иначе появятся два способа закрыть поручение,
  и один из них забудет записать событие в историю.
- **Дедупликация уведомлений вынесена в схему:** `event_key` уникален,
  вставка идёт через `ON CONFLICT DO NOTHING`. Защита от дублей не зависит
  от аккуратности вызывающего кода.
- **Фоновый обработчик — отдельный процесс** с двумя циклами (доставка каждые
  3 секунды, сроки раз в минуту) и блокировкой в Redis. ARQ оставлен в
  зависимостях для тяжёлых задач блока 6.
- **Разбор сроков по-русски** (`app/core/dates.py`): «до пятницы», «через 3 дня»,
  «05.09», «5 сентября 15:00». Результат всегда показывается на подтверждение.

Исправлено по ходу:

- Сообщение «роль подтверждает администратор» показывалось даже тогда, когда
  подтверждать было некому и человек получал доступ сразу. Теперь проверяется
  наличие администратора.
- `05.09` разбиралось как время 05:09 — время теперь распознаётся только с двоеточием.
- Отсутствовал пакет `tzdata`: `ZoneInfo("Asia/Tashkent")` падал и на Windows,
  и в slim-образе. Добавлен в зависимости.

**Проверено:** `smoke_block2.py` — 52 сценария, 0 ошибок. Регрессия блока 1 —
34 сценария, 0 ошибок. Работают все пять служб: postgres, redis, migrate, bot, worker, api.

## 31 августа 2026 (ночь) — Первый вход и два исправления

### Правило первого администратора

Владелец зарегистрировался в боте и застрял: заявка на роль «Ассистент» ушла
на подтверждение, а подтверждать её было некому — администраторов в системе ноль.
Система замыкалась сама на себе.

Исправлено в логике, а не правкой базы: **если в организации нет ни одного
действующего администратора, первый зарегистрировавшийся получает роль ADMIN
дополнительно к запрошенной.** Правило срабатывает ровно один раз — второй
человек уже проходит обычное подтверждение. Проверяется функцией
`has_any_admin()` до создания записи.

Добавлен аварийный скрипт `scripts/make_admin.py <telegram_id> [РОЛЬ]` —
на случай, если администратор потеряет доступ.

### Инцидент: проверочный скрипт удалил боевого пользователя

**Что произошло.** Уборка в `smoke_block1.py` удаляла всех пользователей с
`telegram_user_id >= 900_000_000`, считая такие идентификаторы тестовыми.
Реальный Telegram ID владельца — 976130670, он попал в этот диапазон.
Его учётная запись была удалена прогоном проверки.

**Что сделано.**

1. Проверочный скрипт переписан: все тестовые данные создаются внутри организаций
   с названием `ТЕСТ ...`, уборка удаляет строго по `organization_id`.
   По идентификаторам Telegram больше не удаляется ничего.
2. Добавлен раздел 11 самой проверки: «уборка не трогает боевые данные» —
   сравнивает число настоящих сотрудников до и после.
3. Изоляция проверена сторожевой записью с реальным ID 976130670 в боевой
   организации: прогон её не тронул.
4. В `CONVENTIONS.md` внесён явный запрет на удаление по диапазону идентификаторов.

**Вывод.** Признаком тестовых данных должна быть принадлежность к тестовой
области, а не форма идентификатора. Эвристики вида «большие числа — наши»
рано или поздно совпадают с боевыми данными.

### Состояние после сессии

Проверка блока 1: **34 сценария, 0 ошибок**. База очищена, бот перезапущен
с новым кодом. `BOOTSTRAP_ADMIN_TELEGRAM_ID` снова `0` — роль администратора
теперь выдаёт правило первого вошедшего, отдельная настройка не нужна.

### Инцидент: токен бота попал в репозиторий

**Что произошло.** Владелец вписал боевой токен в `seta/.env.example`. Этот файл
намеренно отслеживается git (это шаблон настроек), а коммит делался через
`git add -A` без просмотра изменений — токен ушёл в оба опубликованных коммита
на GitHub.

**Что сделано.**

1. Токен перенесён из `.env.example` в `.env`, в примере восстановлена заглушка.
2. Добавлен хук `.githooks/pre-commit`, который блокирует коммит при обнаружении
   токена Telegram, ключа OpenAI или самого файла `.env` в индексе. Проверен на
   тестовом файле — коммит отклоняется. Включается командой
   `git config core.hooksPath .githooks`.
3. История переписана в один чистый коммит без токена.
   **Отправка на GitHub с перезаписью осталась за владельцем.**
4. Владельцу передано: токен необходимо отозвать через @BotFather (`/revoke`),
   потому что переписывание истории не гарантирует удаления данных на стороне
   GitHub — старые объекты какое-то время доступны по хэшу.

**Вывод для будущих сессий.** Не использовать `git add -A` не глядя.
Перед коммитом смотреть `git status` и `git diff --cached`. Хук — страховка,
а не замена внимательности.

### Осталось

Отозвать и заменить токен. Задать `BOOTSTRAP_ADMIN_TELEGRAM_ID` — сейчас `0`,
поэтому роль администратора автоматически никому не выдана.
