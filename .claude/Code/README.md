# Код проекта: быстрый старт

Точка входа для ИИ-агента, который начинает работу с нуля. Здесь — карта и
обязательные правила. Подробности живут в файлах, на которые стоят ссылки;
переписывать их сюда нельзя: **два описания одного правила расходятся молча.**

Полный порядок чтения — `AGENTS.md` в корне.

---

## Что это за система

**SETA** — корпоративный Telegram-ассистент руководителя. Продукт существует
ради одного замкнутого цикла:

```
Запрос → Свободное окно → Встреча → Решение → Поручение →
Исполнитель → Срок → Контроль → Проверка → Результат → Сводка руководителю
```

Всё, что не замыкает этот круг, — вторично. Обоснование — `agent/CONTEXT.md`.

## Стек и слои

`aiogram 3` · `FastAPI` · `SQLAlchemy 2` + `Alembic` · `PostgreSQL 16` ·
`Redis 7` · `Docker Compose`. Python 3.13, всё асинхронное.

```
handlers/*.py      собирают ответ и клавиатуру, ничего не решают
      ↓
middlewares/auth   транзакция на апдейт · кто это · какие права
      ↓
services/*.py      все правила системы
      ↓
models/*.py        таблицы PostgreSQL (39 штук)
      ↓
notifications      очередь с защитой от дублей в схеме
      ↓
workers/runner.py  четыре цикла: доставка, сроки, встречи, документы
```

Назначение каждого файла — `STRUCTURE.md`. Модель данных и устройство прав —
`agent/ARCHITECTURE.md`.

## Десять правил, которые нарушать нельзя

Полный свод — `agent/CONVENTIONS.md`. Здесь то, на чём этот проект уже обжигался.

1. **Система считает — ИИ объясняет.** Просрочки, окна, статусы, выгрузки считает
   детерминированный код. Отключение ИИ не должно ломать ни одну функцию.
2. **Три шага прав, и третий обязателен:**
   `grants` → `has_permission(...)` → `can_access_object(...)` / `access_for(...)` /
   `may_read(...)`. Проверяемая формулировка: **в обработчике не должно быть
   сравнений вида `task.assignee_id == user.id`.** Совпадение организации
   доступа не даёт — область права проверяется отдельно.
3. **Каждое правило доступа существует дважды:** проверка одной записи
   (`may_read`) и условие SQL для списков (`visible_filter`). Расходятся они
   молча, поэтому совпадение доказывается прогоном по матрице «запись × человек»
   в smoke-наборе, а не аккуратностью при следующей правке.
4. **Правила живут в схеме, а не только в коде:** уникальный `event_key`,
   частичные уникальные индексы, `EXCLUDE USING gist` на пересечения. Их нельзя
   обойти по забывчивости вызывающего кода.
5. **Ни одного запроса к базе внутри цикла.** Данные для всей выборки грузятся
   одним запросом с `IN`. Образец — `deadlines._load_people`, `slots._load`.
6. **Соединение с дочерней таблицей размножает строки.** `outerjoin` по
   участникам возвращает встречу по разу на участника. Либо `distinct`, либо
   дедупликация по ключу при разборе — иначе счётчики врут.
7. **`esc()` перед вставкой любого текста от человека в сообщение.** Порядок
   всегда `esc(cut(x))`: обрезка после экранирования разрубает `&lt;` пополам.
8. **Никогда `int()` от данных кнопки** — только `callback_int()`.
   Идентификатор из нажатой кнопки проверяется заново всегда.
9. **Бот передаётся обработчику параметром, а не импортом** из `app.bot.loader`:
   глобальный экземпляр держит боевой токен и отправит настоящее сообщение
   даже из проверочного прогона. Это уже случалось.
10. **Схема меняется только миграцией Alembic.** Ручные правки боевой базы
    запрещены. Секреты — только в `.env`.

## Как запустить и проверить

```bash
cd seta
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d
curl http://127.0.0.1:8010/health
```

Порты нестандартные: Postgres 55432, Redis 56379, API 8010.

Перед началом нового блока прогоняются все шесть наборов — список команд
и текущие числа в `agent/STATE.md`, раздел «Как проверить». Везде ожидается
`Ошибок: 0`.

Каждый блок заканчивается своим `scripts/smoke_block<N>.py`. Скрипт обязан
создавать данные только в организациях `ТЕСТ …` и удалять строго по
`organization_id`: **уборка по диапазону `telegram_user_id` однажды удалила
боевого пользователя.**

## Что писать при новой правке

Новая проверка должна **падать до исправления**. Если она проходит и с ошибкой,
и без неё — она ничего не проверяет. Это отдельный шаг, а не формальность:
на этом проекте фальшивой оказывалась проверка индексов («или индекс, или
Seq Scan» проходит при любом исходе).
